# P2 Frontend — Demo Spine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the frontend demo spine: the `/access` persona sign-in, BFF route handlers for sessions, persona switch, reset and job polling, the `/demo` layout with the verbatim demo banner and persona switcher, a jobs page with 2-second polling, and Playwright coverage that proves sign-in/switch/sign-out, no browser-storage tokens, and the banner on every demo route (D-09 frontend, D-10 polling proxies).

**Architecture:** The browser never talks to Railway. Route handlers under `src/app/api/demo/` call the backend with the server-only client (`createApiClient` with `NEWMA_API_URL` and `BFF_SERVICE_TOKEN`) and the session id taken from the HttpOnly cookie `__Host-newma_demo_sid` (dev fallback `newma_demo_sid` on plain http). Server components under `src/app/(platform)/demo/` read the session the same way. Polling handlers return immediately with `Cache-Control: no-store`; the client polls every 2 s until a terminal state. `NEXT_PUBLIC_DEMO_MODE` is read only in `src/lib/demo/mode.ts`.

**Tech Stack:** as P0/P1; `openapi-fetch` client regenerated from the backend P2 spec.

**Spec:** D1 prompt phase card P2; sprint plan §4 (Sessions, Live progress rows), §5 rows D-09/D-10; IP §5.4 steps 4–5; pitfall register 2 and 7.

## Global Constraints

- Demo code only in `src/app/(platform)/demo/`, `src/app/api/demo/`, `src/lib/demo/`; `NEXT_PUBLIC_DEMO_MODE` read only in `src/lib/demo/mode.ts`; the isolation guard stays green. `src/lib/personas.ts` (product vocabulary) lives outside the demo dirs and may be imported by both.
- Banner text, verbatim, on every `/demo/*` page: `Demo with synthetic data. Not evidence of scientific performance, deployment or compliance (PRD front matter).` Labels from prompt §3.1 where a simulated component is shown (`Simulated workflow engine`, `Simulated compute`, `Demo sign-in`).
- No tokens or session ids in `localStorage`, `sessionStorage`, URL or client JS; the session cookie is HttpOnly, Secure (on https), SameSite=Lax, Path=/.
- BFF polling handlers: no streaming, return immediately, `Cache-Control: no-store`; client interval 2000 ms.
- Files < 800 lines, functions < 50 lines, immutable patterns, TDD, conventional commits; work on `main`, no push.

## Review Focus

1. **Cookie on Vercel previews** — `__Host-` requires Secure and no Domain; previews are https so it works; local `next dev` on http must use the fallback name. A unit test covers both branches of `sessionCookieName(isSecure)`.
2. **Server-only leakage** — any client component importing `@/lib/demo/api` must fail the build (`server-only`); the persona switcher calls the BFF route, never the API client.
3. **Expired session** — a 401 from the backend inside the `/demo` layout must clear the cookie and redirect to `/access?reason=expired`, not render a 500.
4. **Polling termination** — the hook must stop on terminal states and on unmount; a test with fake timers asserts no further fetches.
5. **Open redirect** — `/access` only ever redirects to `/demo`; a `next` query parameter, if added later, must be validated as a same-origin path.
