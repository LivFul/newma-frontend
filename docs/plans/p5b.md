## Contract (shared with the frontend/backend P5b plan — identical in both files)

Conventions are those of the P3 Contract (`docs/plans/p3.md`), restated so this table stands alone. All `/v1/*` requests carry `Authorization: Bearer <BFF_SERVICE_TOKEN>` and `X-Demo-Session: <session_id>`. Error envelope `{code, message, details}`. Every route below is tenant-scoped and persona-checked with `require_persona(...)`; a persona outside the allowed set gets **403 `persona_forbidden`** with `details: {persona, allowed: string[]}`. "any" means all eight personas. Writes marked (idem) take `idempotency_key` (`^[A-Za-z0-9._:-]{1,128}$`); a replay returns **200** with the original body and header `Idempotent-Replayed: true`; the same key with a different body is 409 `idempotency_conflict`. Writes marked (event) append a signed provenance event and return its `event_id`. Money is "demo credits" (`unit: "demo credits"`). Every object built from seeded data carries `synthetic: true`.

Shared vocabularies (exact; none of them extends an enum that P2 or P3 already published):

- `ExportPurpose` = `research commercial` (a subset of the P3 `Purpose`). `GateStage`, `GateStatus`, `Decision`, `Purpose`, `RightsStatus` and `PolicyReason = {code, message, rights_record_id | null, remediation | null}` are the P3 ones.
- `FieldStatus` = `disclosed withheld`. `WithheldCode` = the P3 policy reason codes (`no_rights_record consent_withdrawn rights_disputed consent_expired pic_mat_missing purpose_not_permitted jurisdiction_mismatch`) plus `restricted_field` and `stage_not_passed`.
- `FieldDisclosure = {path: "section.field", section, label, status: FieldStatus, value: JSON | null, withheld_reason: {code: WithheldCode, message, rights_record_id | null} | null, synthetic: true}`. A withheld field always has `value: null`; the server never serialises a withheld value, not even masked.
- `ExportStatus` = `active expired suspended` (computed at read time). `LockState` = `open locked`. `ChangeOutcome` = `updated_open_version new_protocol_version unchanged`.
- `Thresholds` = `{potency_um_max: number (>0, ≤1000), replicates_min: integer 1–10, controls_required: boolean, note?: string ≤200}` (closed object, no other keys).
- `ObligationStatus` = `fulfilled due overdue`. `GrievanceCategory` = `obligation_not_met use_outside_agreement consent_concern benefit_not_received other`. `GrievanceStatus` = `open acknowledged`.
- Signature label on every signed object: `"Demo signature, not production key"`.

- `[Agent assumption A-P5B-10]` Charter model: `campaign_charters` stays the head (it mirrors the newest version's thresholds and `credit_quota`, so P3 readers keep working) and `charter_versions` is the history (v1 seeded). `candidates.charter_version` binds each candidate to the version it was selected under (default 1). A version is `locked` when at least one candidate is bound to it. Editing a locked head creates version n+1 (open, no candidates); editing an open head updates it in place (`revision` + 1); identical thresholds return `unchanged`. Gate checks read the version bound to the candidate. A locked version row is never updated (service check plus a trigger). The demo has no candidate-selection endpoint: the four seeded candidates are the selection, so a fresh tenant starts `locked` at v1 and the "before selection" state is the open v2 after the first edit. Thresholds are a closed four-key object.
- `[Agent assumption A-P5B-11]` Quota model: a job reserves its `payload.estimated_credits` (default 10, as P2) from creation and is charged its actual `cost_credits` once terminal (`SUCCEEDED`, `FAILED`, `CANCELLED`); `committed = Σ per job (active or held: max(cost, estimate); terminal: cost)`. `create_job` takes `FOR UPDATE` on the tenant's charter row, re-reads the idempotency key inside the lock, and refuses with 409 `quota_exhausted` when `requested > credit_quota − committed`. A tenant has one charter (jobs count against it); with no charter no quota applies. The scripted agent's `remaining_quota` uses the same function (A-P3-12).
- `[Agent assumption A-P5B-12]` `PUT …/quota` is separate from the protocol version (a budget is not a scientific threshold), carries no idempotency key (idempotent by value; an event only on change), and may cut the quota below what is already committed (remaining goes negative; new jobs are refused).
- `[Agent assumption A-P5B-13]` Obligation fulfilment is a new seeded table `obligation_fulfilments` (one row per obligation period: `fulfilled` with a date, or `pending` with a fixed `due_on`); the status shown is computed at read time (`fulfilled`, `due` when pending and not yet past, `overdue` when past). Fixture dates are fixed, so the seed keeps at least one fulfilled, one due and one overdue row; the "due" row flips to overdue after its date (2027).
